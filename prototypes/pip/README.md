# PIP · 핍 — 단일 파일 프로토타입

빌드도 서버도 없습니다. `PIP.html`을 브라우저로 열면 끝입니다.
모바일 시연은 폰 브라우저로 열면 카메라가 바로 붙습니다.

| 파일 | 내용 |
|---|---|
| `PIP.html` | 온보딩 → 오늘 → 지도 → 기록함 → 리포트 전체 통합본 |
| `나의공간.html` | 보상체계·성장지도 화면만 떼어낸 단독 시연본 (회의에서 이 화면만 볼 때) |

- 앱 이름: **PIP · 핍** — 작은 씨앗, 아주 작은 점, 어린 새가 처음 내는 소리
  - 확장어: `Personalized Initiative Path` (현재 적용) / `Personalized Interest-led Path` (미정, §열린 결정 참고)
- 마스코트: **뱁달이** (뱁새 + 미션 배달)
- 저장: 브라우저 `localStorage`. 사진도 기기 안에만 있고 어디로도 전송되지 않습니다.
- 초기화: 리포트 탭 맨 아래 `프로토타입 초기화`

## 1. 무엇을 구현했나

### 온보딩 — `artifacts/jogak/src/data/onboarding-survey.json` v1.5 그대로
- 은둔 체크리스트 2문항 + 은둔 상황 체크리스트 15문항(0~3)
- 판정도 스펙 그대로: `sc_q1 ∈ {1,2,3,4} AND sc_q2 ∉ {4,5} → 은둔`
- 심각도 `Σ(ss1..ss15)` → 초기 난이도 밴드 (0~10 → L3 / 11~25 → L2 / 26~45 → L1)
- 영역 시드는 문항별 `areas` 가중치로 누적 (내부 라우팅용, 화면 비노출)
- 15문항은 언제든 **건너뛰기** 가능 → 중간 밴드로 처리
- **점수·라벨·단계명은 화면에 한 글자도 노출하지 않습니다.**

### 오늘 — `기획/정본/mission-bank-v2.md` 전량
- 시드 **192개 / 카테고리 27개 / 사진 인증 가능 31개** 를 파싱해 그대로 심었습니다 (문서 통계와 일치)
- 회복단계 → 허용 영역 게이트 (은둔=생활리듬 / 고도고립 +자기돌봄 / 고립위험군 +관계 / 비위험군 +사회진입)
- 밴드 ±1 범위에서 후보 3장을 뽑되 **슬롯과 카테고리가 겹치지 않게** 선택
- 기분 ≤2인 날은 밴드를 깎지 않고 토글 기본값만 '가볍게' (설계명세 §7-1 B안)
- 해봤어요 / **더 작게 바꾸기**(같은 카테고리 하위 난이도로 교체) / 다른 미션 / 오늘은 쉬기
- 회고 3단 = 즐거움 5점 · 뿌듯함 5점 · 한마디(카테고리별 회고 질문 사용)
- 난이도 밴드는 회고 결과로 조용히 ±1. **숫자는 노출하지 않습니다.**

### 지도 — `PRD_보상체계_단일페이지.md` §7 그대로
- 2:1 아이소메트릭 스캔라인 필 렌더러를 새로 작성 (논리 해상도 160×152, 정수 배율만)
- 5개 공간: 방 안 · 집 안 · 집 앞 · 동네 · 더 넓은 곳
- 동네 장면은 §7-5 필수 요소 반영 — 전봇대 + 사인 곡선으로 처진 전선, 아파트(층별 창·옥상 물탱크),
  저층 상가(1층 통유리 + 초록·주황 간판 띠), 노란 중앙선 2줄, 보도블록, 횡단보도, 가로수, 파란 소형 트럭
- 사진은 픽셀로 바꾸지 않고 **실내는 벽 액자(`skewY ±26.57deg`), 실외는 땅에 꽂힌 폴라로이드**로 붙입니다
- 사진 없이 남긴 기록도 빈 프레임으로 자리를 지킵니다

### 기록함
공간별 필터 + 그리드, 탭하면 상세 · **사진만 지우기**(지워도 발자국은 남음)

### 리포트 (기관·미팅용)
자율성 사다리 A0~A4 · 회복 요약 · 영역별 시도 분포 · 보상 규칙표 · 프라이버시 · 열린 결정

## 2. 보상 규칙 (코드 상수 `R` 한 곳에만 존재)

| 행동 | 빛 |
|---|---|
| 시도 (미션 수행) | **+2** |
| 회고 한마디 | **+1** |
| 쉼터 (오늘은 쉬기) | **+1** |
| **사진 인증** | **+0 (의도적)** |
| 공간 개방 | 현재 공간에서 시도 3회 (데모용 임시값) |

**사진 유무가 보상의 양을 바꾸지 않습니다.** 난이도가 높다고, 외출·대인 활동이라고 더 주지 않습니다.
임상적 근거에서 나온 규칙이므로 "게임성을 위해" 조정하지 마세요.
한 번 열린 공간은 다시 닫히지 않습니다.

## 3. 프라이버시

1. 사진은 기기 안에만 저장. **업로드·공유 경로 자체가 없습니다.**
2. 저장 전 캔버스 재인코딩으로 **EXIF(위치·기기 정보) 제거**
3. **흐리게 보관은 저장 시점에 흐림을 굽습니다.** 원본을 따로 두고 표시만 흐리게 하지 않습니다
4. 기록별 **사진만 지우기** — 지워도 시도한 기록은 지도에 남습니다
5. localStorage 용량 초과 시 오래된 사진만 비우고 기록 자체는 유지

## 4. 넣지 않은 것

랭킹 · 다른 사용자와의 비교 · 연속 기록(스트릭) · 미수행 페널티 · 난이도 숫자 노출 ·
진단이나 낙인이 되는 표현(고립·은둔·위험군 등) · 랜덤 뽑기 · 기간 한정 FOMO

## 5. 열린 결정 (팀에서 정할 것)

1. **PIP의 확장어** — `Personalized Initiative Path`(주도성, 현재 적용) vs
   `Personalized Interest-led Path`(관심사). 후자로 가면 온보딩의 관심사 선택을 미션 추천에 실제로 물려야 합니다.
2. **미션 → 공간 매핑.** 미션뱅크에 공간 태그가 없어서 카테고리 단위로 임시 배치했습니다.
   위치가 분명한 것만 고정(`RHYTHM-1A/1B → 방 안`, `SELF-2A/2E → 집 안`, `SELF-2D → 집 앞·동네`,
   `SOC-4D·REL-3E/3F → 더 넓은 곳`)하고, 나머지 78개는 `here`(지금 있는 공간에 놓임)로 뒀습니다. **확인 필요.**
3. **자율성 사다리 임계값.** 원안은 "완료 3일"이지만 데모 한 세션에서 한 칸도 안 열려서
   "완료 3개"로도 열리게 완화했습니다. `ba.ts`가 "임계값은 전부 자의적 초기값(데모)"이라 적어둔 부분입니다.
   **파일럿 전에 되돌릴 지점.**
4. **사진이 붙은 기록과 빛만 남은 기록의 시각적 격차** — 사진 쪽이 더 예쁘면 그 자체가 촬영 압박이 됩니다.
5. **관계 영역에 사진 가능 시드 0개** — 여정 후반의 보상 밀도를 어떻게 채울지.
6. **공간 개방 컷오프 3회**는 데모용 임시 가설. 사용자 테스트 후 조정.
7. **사진 보관 정책** — 기기 변경 시 소실을 허용할 것인가(허용하면 서버 없이 갈 수 있음).

## 6. 아직 안 한 것

- `artifacts/jogak` React 앱과의 연동 — 이 프로토타입은 독립 실행본입니다
