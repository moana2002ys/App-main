# 데일리 체크인 활동 선택 게이트

데일리 체크인 2번째 질문("오늘은 어떤 걸 해보고 싶나요?")은 4개 광의 개선영역이 아니라
시드뱅크 카테고리(구체 활동)를 보여준다. 진단/임상 용어는 절대 노출하지 않음.

## 노출 규칙 (2026-07-15 사용자 확정 — 이전 규칙을 대체)
회복단계별 허용 영역은 누적형: 은둔=생활리듬 / 고도고립=+자기돌봄 / 고립위험군=+관계 /
비위험군=+사회(전 영역). 허용 목록의 **마지막 원소 = 그 단계의 타깃 영역**.

- 설문에는 **타깃 영역 안의 활동만** 노출한다(허용 영역 전체가 아님).
- 하루 4개 미션 = 타깃 영역 2개(고정) + 허용 영역에서 랜덤 2개(다양성).
- 타깃이 금지조건 게이트에 막히거나 컨디션 게이트로 활동이 전부 닫히면 바로 아래
  허용 영역으로 스텝다운.
- 선택 영역은 단계로 고정이므로 `determineTodayArea`는 희망영역 값을 무시한다.

**Why:** 단계별 타깃 영역이 "정복해야 하는" 목표라는 제품 규칙(사용자 확정).
설문 노출과 타깃 산출이 같은 단일 출처(`getStageAllowedAreas`/`getStageTargetArea`)를
쓰지 않으면 고른 활동이 사후에 다른 영역으로 리다이렉트되는 버그가 생긴다.

**주의:** 미션뱅크 설계서 2절 표(은둔=리듬+돌봄 등)는 이 확정 규칙으로 **대체됨** —
문서보다 사용자 확정 규칙이 우선.

## 미션 생성 연동
선택 활동 id는 `activityId`로 흐른다: daily 상태 → 생성 payload/폴백 옵션 →
서버 프롬프트 힌트 + 뱅크의 preferredCategoryId.
- 서버·폴백 모두 preferredCategoryId는 **선택 영역과 활동 영역이 일치할 때만** 반영.
- "잘 모르겠어요" → activityId 없음(타깃 영역은 단계로 자동 결정).

**How to apply:** 단계·영역·게이트 규칙을 바꿀 땐 classifier의 단일 출처와 설문 UI 필터,
다양성 후보 산출이 같은 목록을 공유하는지 세 곳을 함께 확인하고,
4단계×3컨디션 시뮬레이션으로 표와 일치를 검증한다.
