## 2. A급 안건 — 앱 동작이 갈리던 것

### A1. 미션뱅크 시드 절반이 코드에 없다 → **백로그로 기록**

- **문서:** 27 카테고리 / **192 시드** ✅ 직접 확인
- **코드:** `lib/mission-bank/src/categories.ts` — **26 카테고리 / 101 시드** ✅ 직접 확인
- 원본 `docs/mission-bank-v2.json`과 렌더 스크립트가 **저장소에 없다** → "직접 수정 금지" 문구 때문에 교착 상태였음

**조치:** `정본/mission-bank-v2.md`를 **수동 편집 가능한 정본으로 승격**하고, 자동 생성 문구를 폐기했다. 문서 상단에 구현 대비 규모 차이표를 명시하고 **시드 91개 + 카테고리 분리안을 미구현 백로그**로 기록했다.

**남은 일:** 시드 91개를 코드에 반영할지, 목표치를 낮출지 결정.

### A2. 난이도 밴드 상한 → **L5로 통일** ✅

### A3. "컨디션 바닥 → 밴드 −1" → **미채택, B안 확정** ✅

문서 3곳은 "확정", 정본은 "OPEN"이었고, **코드는 둘 다 아니었다.**

**코드의 실제 동작** ✅ 직접 확인:
- 기분은 난이도 계산에 **직접 개입하지 않는다.** `effectiveLevel = clamp(1, min(cap.high, min(5, B + T)))`
- 기분은 **토글 기본값**만 바꾼다 (기분 ≤2 → 기본 '가볍게')
- 즐거움 슬롯만 기분 ≤2인 날 밴드 하단을 1 낮춘다

**결정적 발견:** 이것은 정본 §7-1이 이미 정의해둔 **B안(계획 우선, Martell)과 정확히 일치**한다. 작성자 소견도 B안이었다. 즉 **코드가 이미 B안을 구현**하고 있었으므로 B안을 확정했다.

**조치:** 정본 §7-1을 `[OPEN]` → `[SETTLED] B안 확정`으로 변경(공식·토글 규칙 명문화), §10 OPEN 목록 0번 마감, 온보딩 문서·미션뱅크 문서의 "밴드 −1" 서술 정정.

### A4. 미션 생성 → **로컬 생성 유지** ✅

- **코드:** `artifacts/jogak/src` 전체에서 `generateChallenges` **참조 0건** ✅ 직접 확인. 슬롯 생성은 `ba.ts` `planTodaySlots`로 완전 로컬·결정적
- 서버의 LLM 생성 엔드포인트는 프롬프트·폴백까지 완비됐으나 **호출되지 않는 죽은 경로** 📋
- 현재 LLM은 **사진 인증 칭찬에만** 사용 📋

**조치:** 심화판 §6 LLM few-shot 지시문에 **미채택** 경고 부착. (그 지시문은 "난이도 3택 생성" 방식이라 4슬롯 구조와도 충돌)

**남은 일:** LLM 다양성 재도입 여부는 별도 안건.

## 3. B급 안건

### B1. 컨디션 3단 ↔ 5단 → **코드 매핑 명문화** ✅
코드에 이미 브리지가 있었다 (`ba.ts:40` `moodToCondition`): 기분 ≤2 → `바닥`, =3 → `그저 그럼`, ≥4 → `괜찮음` ✅ 직접 확인.
정본 §1-2의 "변환표 없음"을 삭제하고 이 매핑을 명문화했다. 저장·그래프는 5단 원값, **게이트 판정에서만** 변환 적용.

### B2. 카테고리 26 ↔ 27 → **코드 26개 기준** ✅
`mission-bank-v2.md`의 REL-3D/3G 분리안이 코드에 미반영. 문서 상단에 백로그로 기록.

### B3. 진급 조건 3 → **비하락 + 첫 평가 면제** (수정 불필요)
코드와 정본이 이미 일치 📋. 개선안의 "상승"/"≥3.5" 표현은 아카이브 문서에만 남아 있어 실害 없음.

### B4. "연속 참여" 표시 → **폐기** ✅
정본 §1-1 "스트릭 금지"와 정면 충돌. 코드에도 미구현(`streakDays`는 증가 코드 없는 죽은 필드) 📋.
아카이브 개선안 §2-5에 폐기 표시.

### B5. 보상 루프 ↔ 사이클 리듬 → ⏸ **보류**
보상 설계는 "하루 1미션 · 한 카테고리 3~7일", 사이클은 "하루 4슬롯 · 다양성 강제" 📋. 뱃지 임계 3회 도달 속도가 원설계와 달라진다. **임계값 재산정 필요** — 스토리·보상 정본을 새로 쓸 때 함께 결정.

### B6. 첫 실행 17문항 → **2문항 + Day2 확정** ✅
코드는 첫 화면에서 은둔 체크 2문항만 받고, 15문항은 온보딩 주간 Day2 미션으로 이동. 첫 판정은 보수적 `scoreGatingOnly` 📋.
온보딩 문서 Part 1 도입부를 분할 노출 구조로 정정(문항 전문 17개는 그대로 유지).
