## 1. 컨셉과 톤 [SETTLED]

설계명세 §2-1에서 확정된 내용을 승계한다.

- 전체 앱은 **스토리형(성장형) 컨셉**이다. 온보딩('나 알아가기' 포함)을 스토리로 도입하고, 이후 사이클도 같은 서사·성장 톤을 유지한다.
- **넛징 원칙:** 딱딱한 규칙(밴드·게이트·조정표)은 **내부 엔진에만** 둔다. 사용자가 만나는 층은 전부 **조각이(캐릭터)와 스토리의 목소리**로 감싼다. 리마인더·난이도 넛지·칭찬·진급 제안 모두 시스템 메시지가 아니라 **서사 비트**로 표현한다.
- **자율성 지지형 넛지:** 기본값을 미리 선택해두되 항상 변경 가능하게 하고, "조각이의 제안"으로 프레이밍한다. 통제형(강요·평가) 넛지는 금지한다.
- **보상은 예측 가능한 긍정형:** 취약 인구가 대상이므로 Finch식 **가변(슬롯머신형) 보상을 지양**하고, **누적·무회수·무리셋**(캐릭터 성장·수집·세계 확장)으로 간다.
- 레퍼런스: Finch(펫 돌보기 + 처벌 없는 compassionate design). 상세 비교는 `근거/BA_앱_레퍼런스_비교.md` §4.

## 2. 불변 원칙 (보상 가드레일)

이 원칙들은 **취약 인구 보호를 위한 안전 장치**다. 구현이 이를 어기면 **구현을 고친다.**

1. **누적만 한다.** 리셋·만료·회수 없음. 획득한 뱃지·아이템은 영구 보존.
2. **미완료를 부정적으로 반영하지 않는다.** 벌점 없음, 누적 미완료 표시 없음. 완료된 챌린지만 집계한다.
3. **스트릭(연속) 메커니즘 금지.** 하루 놓쳐도 진척이 사라지지 않아야 한다. → ⚠️ **현재 위반 중, §6-1 참조**
4. **무낙인·무경쟁.** 다른 사용자와 비교하지 않는다. 난이도 숫자(L1~L5)·회복단계명을 화면에 절대 노출하지 않는다.
5. **성장 프레이밍.** 뱃지 문구는 "~이 익숙해졌어요" 같은 상태 변화 서술로 쓴다. 평가·등급 어휘 금지.
6. **무비용.** 결제·구매가 필요한 보상 없음.

## 4. 보상 구조

### 4-1. 보상 단위 — 12개 카테고리

보상은 **광의 4영역이 아니라 12개 세부 카테고리 단위**로 쌓인다. (영역 단위 구현은 코드 리뷰에서 반려된 이력이 있다. 영역 단위로 회귀하지 말 것.)

| id | 영역 | 타이틀 | 뱃지 문구 | 아이템 | 배경 |
|---|---|---|---|---|---|
| `rhythm-anchor` | 생활 리듬 | 하루를 여는 사람 | 하루의 시작점이 생겼어요 | ⏰ 알람시계 | |
| `rhythm-light` | 생활 리듬 | 볕 들이는 사람 | 아침이 밝아졌어요 | 🪟 열린 커튼 | |
| `rhythm-meal` | 생활 리듬 | 끼니 챙기는 사람 | 끼니와 친해졌어요 | 🍚 따뜻한 밥 | |
| `self-walk` | 자기 돌봄 | 동네 산책러 | 산책이 익숙해졌어요 | 👟 운동화 | **1** |
| `self-move` | 자기 돌봄 | 가볍게 움직이는 사람 | 몸이 가벼워졌어요 | 🧘 요가매트 | |
| `self-hygiene` | 자기 돌봄 | 산뜻함 담당 | 산뜻해졌어요 | 🪞 거울 | |
| `self-emotion` | 자기 돌봄 | 마음 관찰자 | 마음을 들여다보게 됐어요 | 📔 일기장 | |
| `self-space` | 자기 돌봄 | 공간 정돈가 | 공간이 정돈됐어요 | 🧹 정돈된 코너 | |
| `self-hobby` | 자기 돌봄 | 취향 탐험가 | 취향과 가까워졌어요 | **취향 분기**(§4-5) | |
| `rel-trust` | 관계 | 안부 전하는 사람 | 마음을 나눴어요 | ✉️ 편지 | **2** |
| `rel-connect` | 관계 | 세상과 연결 중 | 세상과 조금 이어졌어요 | 💬 말풍선 | **2** |
| `social-explore` | 사회 진입 | 나를 찾는 탐험가 | 나를 찾아가고 있어요 | 🎒 가방 | **3** |

### 4-2. 획득 규칙

- **임계값 3회** (`BADGE_THRESHOLD = 3`). 한 카테고리를 **누적 3회** 완료하면 뱃지 + 아이템을 **자동 지급·장착**한다.
- 누적 카운트는 리셋되지 않는다. 뱃지·아이템은 회수되지 않는다.
- 뱃지 획득 시 해당 카테고리에 배경 단계가 걸려 있으면 배경이 함께 확장된다.
- 완료 처리 함수: `applyCompletion()` — 완료 1건마다 `categoryCounts[cat] += 1`, 3에 도달하는 순간에만 지급.

### 4-3. 미션 → 카테고리 분류 (⚠️ 우회 구현)

미션 생성 엔진은 챌린지에 **광의 `area`와 자유 텍스트 `title`만** 부여하고 세부 카테고리 코드를 주지 않는다. 그래서 보상 쪽에서 **완료된 챌린지의 제목을 키워드로 역분류**한다(`classifyChallenge()`).

- 각 카테고리의 `keywords` 배열과 제목을 대조 → 첫 매칭 카테고리
- 미매칭 시 영역별 기본값(`AREA_DEFAULT`): 생활리듬 → `rhythm-light`, 자기돌봄 → `self-walk`, 관계 → `rel-connect`, 사회진입 → `social-explore`

> **이것은 계약이 아니라 우회다.** 코드 주석도 그렇게 명시하고 있다. 근본 해결은 미션 시드에 보상 카테고리 코드를 직접 부여하는 것이다(§6-3).

### 4-4. 포인트

`pointsForLevel(level) = clamp(1,5,level) × 5` → **L1=5 / L2=10 / L3=15 / L4=20 / L5=25**

- 완료 시 누적된다. **현재는 누적 표시 전용**이며 소비처·환산 레벨이 없다.
- 사용자 노출 "경험치 레벨" 개념은 **의도적으로 없다.** `level`은 미션 난이도이고 화면 비노출 원칙(§2-4)이다.

### 4-5. 배경 확장 — 세계가 넓어진다

`BACKGROUND_STAGES = ["방 안", "방 밖", "현관·창밖", "동네"]`

| 단계 | 이름 | 확장 조건 |
|---|---|---|
| 0 | 방 안 | 기본값 |
| 1 | 방 밖 | `self-walk` 뱃지 (산책·외출) |
| 2 | 현관·창밖 | `rel-trust` 또는 `rel-connect` 뱃지 |
| 3 | 동네 | `social-explore` 뱃지 |

- 배경은 **일반 누적이 아니라 특정 성취에 연동**된다 — "안에서 밖으로" 서사를 공간으로 표현하기 위함이다.
- 단계는 내려가지 않는다(`cat.backgroundStage > bg`일 때만 갱신).
- 획득 순간 문구: `세상이 '{배경명}'까지 넓어졌어요`

`self-hobby` 카테고리의 아이템만 **사용자 관심사에 따라 달라진다**(`interestItemId()`).

## 6. 미결 안건

### 6-1. ✅ 스트릭(연속) 표시 제거 — **결정·반영 완료 (2026-07-25)**

**배경.** §2-3은 스트릭을 금지하는데, 앱에는 스트릭이 구현되어 사용자에게 노출되고 있었다. 미완료 시 `0`으로 리셋되므로 **"끊기면 잃는" 경험이 실제로 발생**했다(구현 주석은 "끊겨도 잃는 것 없음"이라 적혀 있었으나 리셋 코드와 모순). 또한 `streakDays`는 **미션 완료 1건마다** 증가해, 하루 4슬롯을 다 하면 하루에 +4가 되는 계산 버그가 있었다 — "일(日)"로 표시되는 값이 실제로는 완료 건수였다.

**결정: 스트릭 UI를 전부 제거하고 누적값만 보여준다.** 취약 인구에게 스트릭 상실은 이탈 유발 요인이므로 원칙을 우선한다.

> 이 항목에는 **"코드 우선" 원칙을 적용하지 않았다.** 그 원칙은 *더 발전된 설계를 따르자*는 뜻이지, *안전 가드레일을 코드가 어겨도 따르자*는 뜻이 아니다.

**반영 내역**

| 위치 | 변경 |
|---|---|
| `pages/growth.tsx` | "이어온 날" 카드 **삭제**, 요약 3칸 → **2칸**(함께한 날 · 모은 조각) |

**남은 정리(선택):** `streakDays` 상태 필드 자체는 남아 있다(`store.tsx`, `reflection.tsx`). 이제 **어디에도 표시되지 않는 미사용 필드**이므로 동작에 영향은 없으나, 정리하려면 증가·리셋 코드까지 함께 제거하면 된다.

### 6-2. 뱃지 임계 3회 재산정 — ⏸ **보류 (2026-07-25 · 기록만)**

> **팀 결정:** 문제를 문서에 남겨두고, 처리 방향은 이후 회의에서 정한다. 아래 분석은 그 논의를 위한 자료다.

원 설계(`근거/character_reward_design.md` §1)는 **"한 카테고리에 3~7일 머문다 · 하루 1미션"**을 전제로 임계 3회를 잡았다. 그런데 현재 사이클은 **하루 4슬롯 + 다양성 강제**(설계명세 §6-1·§6-3)라 전제가 깨졌다.

**더 중요한 문제 — 은둔 단계 사용자의 보상 접근성**

허용 영역이 단계별로 제한되므로(`STAGE_ALLOWED_AREAS`), 은둔 단계에서는 **생활 리듬 영역만** 열린다. 그 결과:

| | 은둔 단계에서 도달 가능 |
|---|---|
| 보상 카테고리 | **3개**뿐 (`rhythm-anchor`, `rhythm-light`, `rhythm-meal`) |
| 캐릭터 아이템 | **1개**뿐 (파란 모자) |
| 방 가구 | **3개** (침대·테이블·조명) |
| 배경 확장 | **불가능** — 1·2·3단계가 전부 자기돌봄 이상에 걸려 있어 **영원히 "방 안"** |

가장 취약하고 **가장 오래 머무를 층**이 보상을 가장 적게 받고, 세계 확장 서사도 경험하지 못한다. 온보딩 주간의 고정 미션(자기돌봄 포함)으로 일부 완화되지만 임계 3회에는 못 미친다.

**검토할 선택지**

- 생활 리듬 영역에 보상 카테고리를 추가한다 (미션뱅크 생활리듬은 6개 카테고리인데 보상은 3개뿐)
- 배경 1단계를 생활 리듬 성취로도 열리게 한다
- 단계별로 임계값을 다르게 둔다 (은둔 2회 / 이후 3회 등)

### 6-3. 보상 카테고리와 미션뱅크 카테고리가 어긋난다

| | 개수 |
|---|---|
| 미션뱅크 카테고리 (`lib/mission-bank`) | **26개** |
| 보상 카테고리 (`lib/rewards.ts`) | **12개** |

그래서 §4-3의 키워드 역분류가 필요해졌다. 부작용:

- `social-explore`는 **`keywords`가 빈 배열**이라 키워드로는 절대 매칭되지 않고, 사회진입 영역의 기본값으로만 도달한다. 즉 **사회진입 영역의 모든 미션이 한 카테고리로 뭉친다.**
- 제목 표현이 바뀌면 분류가 조용히 달라진다.

**근본 해결:** 미션 시드에 보상 카테고리 코드를 직접 부여하고 챌린지에 실어 보낸다. (미션뱅크 백로그와 함께 처리 — `00_결정필요_안건.md` A1)

### 6-4. 스토리 서사가 아직 없다

컨셉(§1)은 확정됐지만 **실제 서사 자산이 없다.**

- 챕터 구조 / 조각이 캐릭터 설정(성격·말투) / 온보딩 스토리 카드 문안 / 카피 톤 가이드
- 현재 서사 톤은 개별 문구에 흩어져 있다 (예: "여기까지 온 건 전부 당신이 해낸 거예요", "안에서 밖으로, 조금씩 세상과 이어지고 있어요")

→ **다음 작업 후보.** 흩어진 문구를 톤 가이드로 수렴시키는 것부터 시작하면 된다.
