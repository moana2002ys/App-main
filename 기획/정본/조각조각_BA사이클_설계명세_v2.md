## 0. 대상·개입 근거 (정책 리서치 반영) [SETTLED]

_출처: 정민&예슬&지혜 회의록(현지혜 리서치) — 김성아 외 (2022) 「고립·은둔 청년 지원사업 모형 개발 연구」(정책보고서 2022-35), 김성아 외 (2023) 「고립·은둔 청년 실태조사 연구」(용역보고서 2023-124), 보건복지부·한국보건사회연구원._

대상은 고립·은둔 청년. 정책 리서치의 **지원 목표 × 핵심 서비스** 축이 우리 4개 회복 영역의 근거다:

| 지원 목표(당사자) | 핵심 서비스(리서치) | 대응 회복 영역 |
|---|---|---|
| a) 자기 회복·일상유지 (개인) | 자기 이해·탐색·내면 치유, 자신감 회복·동기부여, 수면·식사·정리정돈·위생 등 일상생활관리, 신체 건강 회복 | **생활리듬 · 자기돌봄** |
| b) 사회 재적응·관계형성 (관계) | 대인관계·사회성 재학습, 치유적 사회적 관계망 형성 | **관계** |
| c) 사회참여·통합·자립 (사회) | 자기개발·진로탐색·취창업 교육, 일경험·성공경험, 지역 기반 참여, 자조모임 | **사회진입** |
| d) 필요 시 별도 연계 | 생계급여·긴급복지·주거·의료 서비스 연계 | (앱 밖) 위기 분기 → 자원 연결(§1) |

시사점: 우리의 영역 진행 순서(생활리듬 → 자기돌봄 → 관계 → 사회진입)와 누적 허용 영역 설계(§4)는 이 개입 위계와 정합한다. "필요 시 연계"는 앱이 대신하지 않고 위기 분기·기관 대시보드로 연결한다.

## 1. 불변 원칙 & 가드레일 (깨면 안 됨) [SETTLED]

### 1-1. 프레이밍 가드레일
- **실패 프레이밍 전면 금지.** 건너뛴 미션은 절대 "실패"가 아니다. skip은 (명시적 skip만) 회피 *신호*로만 카운트하고 사용자 잘못으로 노출하지 않는다. 벌점 없음. 밴드 로직에 하향(−1)이 존재하지만 **"강등/하향"으로 절대 표시하지 않는다**(성장형 문구로만).
- **스트릭(연속) 메커니즘 금지.** 게이미피케이션은 보조(수집·마스코트 온기)일 뿐 핵심 루프가 되지 않는다.
- **"기분이 아니라 계획대로"(Martell)** 가 사이클의 척추. 미션 전에 "할 기분이세요?"를 묻지 않는다.
- **낙인 언어 비노출.** 사용자 화면에 치료/증상/우울증/고립/은둔/환자, 난이도 숫자(L1~L5), 단계명을 절대 쓰지 않는다. (보고용 자료 덱에서는 이론 인용 자유.)
- **무비용.** 결제·구매 미션 금지.
- **입력 부담 최소.** 시간대별 표 지양, 탭 중심.
- **위기 신호 최우선 분기.** 자해·자살 표현 감지 시 일반 미션 중단 + 자원 연결. 이 앱은 치료·진단 서비스가 아니다. (실제 UX 흐름은 §10 OPEN.)

### 1-2. 척도 규약 [SETTLED]
- **기분 체크**: 5단계(7·10단계 아님). 값: 1 매우 별로 / 2 별로 / 3 보통 / 4 좋음 / 5 매우 좋음. 저장·비교·그래프 모두 이 5단 원값 사용.
- **기분 → 컨디션 어휘 변환** [SETTLED · 2026-07-25 현행 구현 기준]: 미션뱅크 게이트가 3단 어휘(`바닥`/`그저 그럼`/`괜찮음`)로 라벨링되어 있어 브리지가 필요하다. 구현(`artifacts/jogak/src/lib/ba.ts` `moodToCondition`)과 동일하게 확정한다.
  - 기분 **≤ 2** → `바닥`  /  기분 **= 3** → `그저 그럼`  /  기분 **≥ 4** → `괜찮음`
  - 저장·그래프는 5단 원값을 쓰고, **카테고리 게이트 판정에서만** 이 변환을 적용한다.
- **P/M(즐거움/뿌듯함) 슬라이더**: 0–10 연속, **초기값 없음**(핸들은 터치 시 등장, 앵커 편향 방지), 완료 미션에만. 내부 5구간 매핑(§7-2).
- **graded task**: 난이도 기본값은 항상 낮게("가볍게"). 성공확률 최대화가 먼저, 밴드는 숙달 조건에서만 오른다(Lejuez BATD 위계 논리).

### 1-3. 근거 인용 규칙 (팀 확정, 필수) [SETTLED]
- 인용은 **peer-review 저널 또는 표준 치료 매뉴얼만** (Lejuez BATD 2001, Martell, Beck 1979, JMIR/World Psychiatry 메타분석, Moodivate/Dahne RCT 등).
- **학위논문(석·박사)은 근거에서 명시적으로 배제.**

## 2. 시스템 개요 & 데이터 흐름 [SETTLED]

규칙 기반 분류기가 회복 단계·난이도(밴드)·금지조건을 판정하고, 그 제약 안에서 LLM이 개인화 미션을 생성한다. 네 회복 영역: **생활리듬 · 자기돌봄 · 관계 · 사회진입.**

핵심 구조 결정: **BA 이중 평정(P/M)이 두 개의 독립 적응 레이어를 구동한다.**
- **M(숙달·뿌듯함) → 밴드(난이도)** 이동
- **P(즐거움) → 즐거움 슬롯 추천기(활동 선택)** 구동
- 이 분리가 조정표 단순화·콜드스타트 주인·난이도 노브 이중화를 동시에 해소하고, 규칙 전체를 "완료→하향 없음"으로 만들어 실패 처벌 금지 원칙과 정합시킨다.

```
[담당:온보딩] 가치 선택 · 약 1주 기분·P/M 베이스라인 · 완료/skip 패턴
   ↓  (인터페이스 5필드 — §3)
데일리 설문(기분 5단 + 영역/활동 선택, 2문항)
   ↓
미션 제안(타깃2 + 즐거움1 + 회피1[2주차~]) + 난이도 토글 + 시간대 탭
   ↓
수행 → 인증(P/M 슬라이더 평정) 또는 건너뜀(회피 프롬프트)
   ↓
다음날 밴드 조정(day_result 3분기) · 주1회 진급 배치
   ↓
마이페이지(기분×완료 오버레이) → 다음 날 동기로 순환
```

### 2-1. 컨셉·톤 [SETTLED — 2026-07-24]
전체 앱은 **스토리형(포켓몬 같은 성장형)** 컨셉으로 간다. 온보딩('나 알아가기' 포함)을 스토리로 도입했고, 이후 사이클도 같은 서사·성장 톤을 유지한다.
- **넛징 원칙:** 딱딱한 규칙(밴드·게이트·조정표)은 **내부 엔진에만** 두고, 사용자가 만나는 층은 전부 **조각이(캐릭터)와 스토리의 목소리**로 감싼다. 리마인더·난이도 넛지·칭찬·진급 제안 모두 시스템 메시지가 아니라 **서사 비트**로 표현.
- **자율성 지지형 넛지:** 기본값 미리 선택 + 항상 변경 가능 + "조각이의 제안"으로 프레이밍. 통제형(강요·평가) 넛지 금지(§1).
- **보상은 예측 가능한 긍정형:** 취약 인구 → Finch식 가변(슬롯머신형) 보상 지양, **누적·무회수·무리셋**(캐릭터 성장·수집·세계 확장). 상세는 별도 넛징/보상 설계 문서에서 재설계 예정(기존 `character_reward_design.md`는 최소 참고).
- 레퍼런스: Finch(펫 돌보기 + 처벌 없는 compassionate design)가 이 접근의 검증 사례. BA 앱 근거는 §11.

## 3. 상태 모델 & 인터페이스 계약

### 3-1. 온보딩 → 사이클 인터페이스 (계약) [담당:온보딩]
온보딩(스토리텔링 심리교육 + 가치 명료화 + 첫 실행 설문 + '나 알아가기')은 별도 담당. 사이클은 아래 산출값만 받는다. 사이클 개발 시 **스텁 값**으로 두고 독립 개발한다. 각 값의 **실제 산출 규칙은 §4**(온보딩 기준 문서 Part 1·2)에 정의.

| 필드 | 타입(예시) | 산출 위치 | 용도 |
|---|---|---|---|
| `is_secluded` (은둔 여부) | bool | §4-1 은둔 체크(2문항) | 은둔 최우선 규칙(밴드 L1 고정, 관계·사회진입 잠금) |
| `stage` (회복단계) | enum(은둔/고도고립/고립위험군/비위험군) | §4-3 나 알아가기(25문항 44/60 컷오프) | 허용 영역·타깃 영역·게이트 결정 |
| `band` (첫 난이도밴드) | L1~L5 | §4-2 심각도 총점(0~45) 3구간 | 챌린지 시작 밴드 |
| `area_seed` (영역 시드) | 영역별 가중 점수 | §4-2 15문항 주/보조영역 가중 | 타깃/우선영역 랭킹, 콜드스타트 |
| `gates` (금지조건) | 외출/대면/전화/문자/관계대면 플래그 | §4-2 은둔신호 + §4-4 게이트 표 | 후보풀 필터 |
| `mood_baseline` | number(1–5) | 온보딩 1주 기분 | 마이페이지 그래프 기준선 |

### 4-2. 첫 실행 17문항 채점 (내부 계산 · 화면 비노출)

**(1) 심각도 총점(비진단)** = 15문항 합(0~45 = 각 0~3 × 15). → 첫 난이도밴드(설계 편의상 자의값, 파일럿 보정 전):

| 심각도 총점 | 심각도 | 첫 밴드 | 뜻 |
|---|---|---|---|
| 0 ~ 10 | 낮음 | L3 ~ L4 | 비교적 활동적 — 조금 도전적인 미션부터 |
| 11 ~ 25 | 중간 | L2 | 중간 난이도로 시작 |
| 26 ~ 45 | 높음 | L1 | 가장 작고 쉬운 미션부터 |

**(2) 은둔신호** = 심각도 총점과 다름. 15문항 중 **문항 5·6·14**만 모은 영역 시드 태그. 높으면 **관계·사회진입 게이트 잠금** 판단에만 사용.

**(3) 영역 시드** = 각 문항 점수를 §4-1 표의 주영역(1.0)+보조영역(0.3~0.5)에 나눠 더함. 예: 문항5('가족 없을 때만 움직여')에 3점 → 은둔신호 +3.0, 관계 +1.5, 생활리듬 +0.9(주1.0×3). 합계 높은 영역 = 지금 부담 큰 영역 → 그쪽부터 낮은 난이도로 진입. (라우팅용 설계값, 검증된 하위척도 아님.)

**(4) 은둔 최우선 규칙** = 은둔 체크 '은둔' 양성이면 심각도 밴드와 무관하게 **밴드 L1 고정 + 관계·사회진입 잠금**(가족 트랙 L1까지만).

**(5) 매일 조정** = 컨디션 '바닥'(기분 ≤2)이라도 **전체 밴드를 깎지 않는다.** 대신 토글 기본값을 '가볍게'로 내리고, 즐거움 슬롯의 밴드 하단만 1 낮춘다(§7-1 B안 확정). 직전 회고 결과에 따른 다음날 밴드 ±1은 **사이클 §7-3(day_result 3분기)를 따른다**(온보딩 문서 Part 3 조정표 미채택).

### 4-5. 분류기 경계 (온보딩 Part 3 ① 채택) [SETTLED]
온보딩·데일리 설문 계산값(은둔 여부·외출부담·심각도 밴드·영역 시드·회복단계)은 **규칙 기반 분류기(코드 구현, LLM 아님)**로 넘어간다. 분류기는 **[챌린지 영역 + 트랙 + 난이도밴드 + 금지조건]까지만** 정한다. 그 다음(미션 문안 생성)은 LLM 몫(§6). 이 경계가 "임상 인접 판단은 설명 가능해야 한다"는 원칙(§8 로드맵)을 지킨다.

## 5. 데일리 설문 (매일, 2문항) [SETTLED — v2 개정]

1. **기분/컨디션** — 5단계 탭 1회(§1-2). 임계 재정의(3단→5단 통일, 어휘 변환은 §1-2 브리지표):
   - 난이도 "바닥" 판정 = **기분 ≤ 2**
   - 카테고리 최소 컨디션 게이트 = **기분 ≥ 3**
2. **활동 선택** — "오늘은 어떤 걸 해보고 싶나요?"
   - 타깃 영역 하위 활동만 노출, 카테고리 게이트 통과분만 표시, 전부 닫히면 스텝다운, "잘 모르겠어요" 가능. [유지]
   - **activityId → 슬롯 매핑:** 선택 활동은 **타깃 슬롯 1번**에 고정 반영. 즐거움 슬롯 후보와 소재가 겹치면 **타깃 우선**, 즐거움은 차순위 소재로 대체(같은 날 소재 중복 금지 — diversity와 정합).
3. **관심사 문항 제거** → 온보딩 수집 + **주 1회 갱신 카드**("요즘 빠져있는 게 있나요?", 건너뛰기 가능)로 이동. P 높았던 소재는 관심사 풀에 자동 추가.
   - 관심사(선언) vs P 누적(행동) 충돌 시: **P 데이터 우선**, 단 갱신 직후 3일간 새 관심사에 부스트 가중치.
   - "활동 후 기분"은 데일리가 아니라 사후 P/M이 담당(BA 표준: 평정은 활동 직후).

### 5-1. 가치(value)·관심사(interest) — 포착·반영 규칙 [SETTLED — 2026-07-24, (다) 확정]
둘은 다른 데이터다. **가치 = "이 영역이 왜 중요한가"(영역 단위, BA value clarification)**, **관심사 = "무슨 소재를 좋아하나"(취향 소재, 즐거움 슬롯용)**. 사이클에서 가치를 **재설문하지 않는다**(부담 큰 파트 회피) — 대신 아래 두 채널로 변화가 자연히 잡힌다.

**데이터:** `values[domain]` = 영역별 가치 태그/문구(온보딩 수집). 아직 안 열린 상위 영역은 빈 값.

**포착(capture) — 값이 생기거나 바뀌는 지점(이때만):**
1. **온보딩**: 현재 단계 근처 영역의 `values` 최초 수집. [담당:온보딩]
2. **진급 시(§8)**: 새로 열리는 영역의 가치를 **진급 동의 탭 직후 1문항**으로 수집("○○, 왜 해보고 싶어요?" 탭 1회). 진급 흐름(동의+게이트 재확인)에 자연히 얹힘 = 새 영역 가치 포착.
3. **관심사(소재)**: 주 1회 갱신 카드(§5-3) + 완료 P 높은 소재 자동 추가. (가치 아님 — 즐거움 슬롯 가중치로만.)
- 이미 열린 영역의 가치는 **재질문하지 않는다.** 변화는 위 2·3으로 간접 반영.

**반영(application) — 값이 쓰이는 곳:**
1. **타깃 슬롯 미션 문구**: "당신이 고른 ○○을 위한 조각 — [value]"로 매일 상기. (BA 장기 효과 유지)
2. **진급 제안 문구**: 새 영역 제안을 그 영역의 (곧 물을/물은) 가치로 프레이밍.
3. **가치가 빈 값이면**: 가치 연결 없이 중립 문구("오늘의 조각")로 노출, **재질문하지 않음**.
4. **관심사**: 즐거움 슬롯 소재 가중치(§5-3, §7-3 `P_pool`) — 가치와 분리.

## 6. 미션 생성 (하루 4슬롯) [SETTLED — v2 개정]

> **온보딩 Part 3 ②와의 관계 (팀 결정 2026-07-24).** 온보딩 문서 Part 3는 "분류기가 영역·밴드·금지조건을 정하면 LLM이 **같은 영역에서 난이도 낮·중·높 3개를 만들어 1개 선택**"을 제안한다. 이는 사실상 *영역 1개 × 난이도 변주*라, BA 성분(즐거운 활동·회피 스케줄링)을 담는 우리 **4슬롯 구조와 충돌**한다. → **우리 4슬롯이 상위 구조로 채택되고, Part 3 ②의 3택 생성 모델은 미채택.** 다만 세 요소는 이렇게 흡수한다:
> - **자율성(Part 3 ③)**: "3개 중 1개"가 아니라 **데일리 활동 선택 + 4슬롯 중 실행 선택 + 미션별 난이도 토글(가볍게/보통/도전)** 로 구현. "난이도 3택"의 취지 = 우리 토글과 동일(같은 미션의 난·중·고 변주).
> - **약간의 계획 세우기**: 미션 선택 즉시 **시간대 탭**(아침/점심/저녁) 1회 + 단계별 어디서/누구와(§6-6). 시간·장소·순서를 쓰게 하지 않음.
> - **안전망(LLM 실패 → DB 그대로)**: 우리 폴백(§6-5)과 동일.

### 6-1. 슬롯 구성 (v1 타깃2+랜덤2 → v2 타깃2+즐거움1+회피1)
> 참고: v1의 "랜덤 2"는 **영역 선택이 랜덤**이었지 난이도가 랜덤은 아니었다(난이도는 밴드 제약 안, 타깃 2는 서로 다른 난이도). v2는 그 랜덤 2 자리를 즐거움·회피로 교체.
| 슬롯 | 내용 | 사용자 배지 |
|---|---|---|
| 1–2 타깃 | 타깃 영역, 난이도 서로 다르게. 슬롯1 = 설문 선택 활동 반영 | "내가 고른 영역" + 가치 연결 |
| 3 즐거움 | `P_pool` 가중치 상위 소재에서 추천 | "최근 즐거움 점수가 높았어요" |
| 4 회피 | 반복 skip 대상을 한 단계 작게 쪼갠 시드(더 낮은 밴드) | "계속 미뤄왔던 조각, 더 작게 쪼갰어요" |

- **첫 주는 3슬롯**(회피 미노출). "2주차" 기준 = `cycle_start_date`. 단 온보딩 `skip_pattern`에 같은 세부영역 명시적 skip ≥ 2회면 1주차부터 조기 활성화.
- 2주차 이후에도 skip 데이터가 없으면 슬롯4를 타깃 다양성 미션으로 대체(회피할 게 없는 건 좋은 신호).
- **첫 주 3슬롯 UI는 "슬롯이 잠겨 있다"는 결핍 프레이밍 금지**(§10-7).

### 6-2. 후보풀 & 완화 순서 (복각 핵심)
```
후보풀 = 허용영역 ∩ 게이트(외출·대면·전화·관계대면) 통과 시드
# 게이트·영역 제약은 어떤 경우에도 완화하지 않는다 (§1).
슬롯을 채우다 다양성 제약(§6-3)을 못 맞추면 완화 순서:
  1) 다양성 제약을 "1개 축"으로 완화
  2) 다양성 제약 완전 해제
  3) 그래도 후보 < 슬롯 수 → 슬롯 수 축소 (빈 슬롯·중복 시드 노출 금지)
```

### 6-3. 영역 내 다양성 (저단계 붕괴 수용)
- 저단계(은둔)는 4슬롯이 전부 생활리듬으로 수렴하는 것을 정답으로 받아들인다.
- 시드에 `diversity_key` 3필드: `소재`(관심사 태그도 이 축 값) · `시간대`(아침/점심/저녁) · `감각`(빛/소리/몸/촉감).
- **다양성 정량자(집합적, pairwise 아님):** 그 날 채워진 슬롯들이 **최소 2개 축 각각에서 서로 다른 값을 2개 이상** 가지면 충족.

### 6-4. skip의 조작적 정의 [SETTLED — v2 §9-3]
- **명시적 skip** = 건너뛰기 탭 또는 회피 프롬프트 응답 → 회피 후보 자격(2주 창 내 같은 미션/세부영역 2회) 카운트 **포함**.
- **무응답일**(앱 미접속 포함) = 회피 데이터 **제외**, 밴드의 미완료 경로에는 포함.
- 회피 후보 우선순위 = skip 횟수 내림차순, 동률 시 최근성.

### 6-5. 생성 파이프라인 (서버) [유지 — v1 §3-3~3-5 전문]

**단계 1) LLM 생성 (5초 타임아웃)**
- 프롬프트로 전달하는 입력: 회복단계 · 허용/타깃 영역 · 밴드(범위) · 금지조건 · 온보딩 답 · 오늘 기분 · 관심사 · 데일리 설문에서 고른 활동(`activityId`).
- 시드뱅크의 **열린 카테고리와 시드를 few-shot 예시로 제공.** 단, **복붙 금지 — 변주(개인화)해서 생성**하도록 지시.

**단계 2) 결정적 검증·수리 (코드, LLM 출력 신뢰 안 함)**
- **영역 검증:** 생성물의 영역이 허용 목록에 없으면 **버린다.**
- **난이도 클램프:** 난이도는 그 영역의 밴드 범위로 클램프(영역캡 §7-1 적용).
- **다양성 편중 방지:** 후보 영역이 2개 이상이면 영역당 1개까지만.
- **한 활동 원칙:** "~하고 ~하기", "~하면서" 등 병렬 활동 감지(`hasParallelActivities`) → 검증된 시드로 교체(`repairMission`). 수리 후에도 위반이 남으면 **전체 폴백.**
- **제목 중복 제거.** 구성(타깃 N + 슬롯 구성)이 안 채워지면 **전체 폴백.**
- **구성 밸런스(`enforceComposition`):** 관심사 반영은 **즐거움 슬롯 + 타깃 1개까지**, **사진 인증 가능한 시드 1개 이상**이 되도록 결정적으로 보정. (대체 가능한 시드가 있을 때 교체하는 best-effort — 대체 시드가 없는 극단 케이스는 원문 유지.)

**단계 3) 폴백 (안전망)**
- LLM 실패·타임아웃·검증 실패 시 → 시드뱅크에서 **같은 구성 규칙으로 결정적 선택**(`selectDiverseFallbackMissions`).
- 서버 자체가 실패하면 → 클라이언트가 **로컬 폴백 뱅크** 사용.
- (온보딩 문서 Part 3 ③의 "LLM 실패 시 DB 항목 그대로 노출" = 이 폴백과 동일.)

**미션 문구 규칙 [유지 — v1 §3-5]**
- 아주 작은 행동(프롬프트 목표 5~15분). 실제 소요시간은 난이도별 기본값 2~15분, LLM 제시값은 최대 30분까지 허용.
- 구체적·실행 가능. **회고 질문 한 줄 포함.**
- 지시·명령·평가·비교·재촉 표현 금지("~해야 한다", "꼭", "매일" 등).
- 기분 바닥(≤2)이면 **기록형(쓰기·고르기·표시) 위주.**
- 회피 슬롯 문구는 **접근·긍정 프레이밍만**(§6-8b), "회피 극복/문제 직면" 금지.

**단계 4) 사진 인증 칭찬 [유지 — v1 §5]**
- 완료 후 사진 업로드 시 LLM(12초 타임아웃)이 사진에서 보이는 것을 짚어 1~2문장 칭찬 생성.
- 사진이 미션과 무관해 보여도 지적하지 않고 시도 자체를 칭찬(실패 처벌 없음).
- 결정적 가드: 규정 언어(고립·은둔·환자)·난이도 표기(레벨·단계)·연속/스트릭 표현이 섞이면 즉시 폐기하고 준비된 칭찬 문구로 대체.
- 분석 실패 시에도 완료는 그대로 인정.
- 각 미션 공통 사용자 입력: **난이도 토글(가볍게/보통/도전, 기본 가볍게)** + **시간대 탭(아침/점심/저녁) 1회** → 리마인더. 시간·장소·순서는 쓰게 하지 않는다.

### 6-6. 계획을 어디까지 반영할까 — 3층 모델 (2026-07-24 논의)

**핵심 판단: 계획의 능동 성분은 세세한 계획표가 아니라 "언제·어디서" 한 줄(실행 의도, implementation intention)이다.** 그만큼만 넣고 나머지는 사후·선택형으로 미룬다.

| 층 | 내용 | 상태 |

| **1층 — 실행 의도(언제/어디서)** | 시간대 탭(아침/점심/저녁), 단계별 "어디서"(고립위험군+). 탭 1회, 자유입력 없음 | **[SETTLED]** — 건너뛰기 가능 + 기본값 넛지(§6-7) |

**3층 주간 계획 설계 옵션 (미채택, 회의용):**

- (나) 비위험군 한정 "이번 주 해보고 싶은 조각 미리 골라두기" 선택형(스킵 가능). 캘린더 아님, 탭 몇 번.

### 6-7. 리마인더 & 즉시 기록 넛지 (2026-07-24 논의)
**전제(핵심):** 1층의 "건너뛰기 가능 + 기본값 넛지"가 작동하려면, **완료 즉시 앱에 기록하는 습관**이 깔려야 한다. → 온보딩에서 "하면 바로 조각이에게 알려주기"를 스토리로 학습시키고([담당:온보딩]), 홈 미션 카드에서 **1탭 완료 기록** + 캐릭터 즉시 반응(보상)으로 기록을 끌어당긴다(푸시 의존↓).

**리마인더 설계(사용자 제안 검토 반영):**
- **미션당 1회 = 시작 큐**만. 계획한 시간대 시작 시점에 조각이 톤으로: "이제 슬슬 해볼까요?" (실행 의도 지지 = 근거 있는 넛지).
- **완료 재촉 알림은 미션별로 보내지 않는다.** 대신 **하루 1회 저녁 마무리 체크인**으로 통합: "오늘 맞춘 조각 있으면 알려줘 🙂"(궁금해하는 캐릭터, 선택). 이게 즉시 기록 습관의 앵커도 됨.
- **금지:** "완료 인증을 해주세요!"처럼 **명령형·미완료 지적형 문구 금지**(§1 재촉 금지 + 미완료 독촉 금지). "안 했다"로 읽히는 알림은 절대 안 보냄.
- **하루 총 캡 = 2회**(시작 큐들 + 저녁 체크인 1회), 쉬운 opt-out, 톤은 회고형.

> **[승인 필요] 리마인더 강도:** "미션별 시작 큐 + 저녁 통합 체크인 1회"(추천, 위) vs "시작 큐만"(더 가벼움) vs "사용자 제안대로 미션별 시작+완료 2회"(부담 위험). 회의에서 택1.

### 7-1. 오늘의 시도 난이도 합성 — **[SETTLED · 2026-07-25] B안(계획 우선) 확정**
밴드 B와 토글 T(가볍게 −1 / 보통 0 / 도전 +1, 기본 가볍게)를 합성한다. **기분은 실제 난이도에 개입하지 않고 토글 기본값만 바꾼다.** 현행 구현이 이미 B안이므로 이를 정본으로 확정한다.

- **공식:** `오늘의 난이도 = clamp(1, min(영역캡.high, min(5, B + T)))`
  - 구현: `artifacts/jogak/src/lib/ba.ts` — `Math.max(1, Math.min(cap.high, Math.min(5, raw)))`
  - `TOGGLE_DELTA = { 가볍게: −1, 보통: 0, 도전: +1 }`
- **기분의 역할:** 토글 **기본값**만 결정한다. 기분 ≤2 → 기본 '가볍게', 넛지 상태 → '보통', 그 외 '가볍게'. 사용자가 직접 '도전'을 고르면 그대로 존중한다(선택권 존중, §1-1).
- **즐거움 슬롯 예외:** 밴드 하단을 쓰며, 기분 ≤2인 날 하단을 1 더 낮춘다.
- 공통 전제(확정): 토글은 밴드의 하루짜리 ±1 표현, 영역캡(아래)은 항상 상한, 클램프는 마지막에 한 번.

아래 A/B/C 비교표는 **결정 근거로 보존**한다.

| | A안 합산형 | B안 계획 우선(Martell) | C안 안전 우선(Beck/graded) |
|---|---|---|---|
| 공식 | `clamp(B + 기분보정 + T)` | `clamp(B + T)` — 기분은 실제 난이도 불개입, **토글 기본값만** 기분 따라(≤2면 기본 '가볍게' 강제) | `clamp(B + T)`이되 기분 ≤2인 날 **'도전' 숨김**(상한 B) |
| 장점 | 단순·예측가능 | BA 원칙 최충실, 기분 나쁜 날 도전 성공의 교정 경험 허용 | 저단계 보호 최대 |
| 단점 | 기분 나쁜 날 도전 골라도 조용히 '보통'됨(선택 무력화) | 기분바닥+도전 실패 위험을 유저가 짊어짐 | 선택지 제거가 "오늘은 안 된다" 평가로 읽힐 위험(§1 낙인) |

- **결정(2026-07-25): B안 채택.** BA 원칙(Martell "기분이 아니라 계획대로")과 §1-1 선택권 존중에 동시 부합하며, 현행 구현이 이미 B안이다. 실패 위험은 미완료 −1·재축소가 흡수한다.
- 온보딩 문서 Part 1의 "컨디션 바닥이면 전체 밴드 −1"은 위 A안(기분보정)에 해당 → **미채택.** 기분으로 밴드를 직접 깎지 않는다.
- **영역캡** `capBandForArea` [유지]: 관계 영역은 은둔 L1 고정, 고도고립 최대 L2. `forceLowBurdenArea`: 2일 연속 skip 다음 날 타깃을 생활리듬으로 강제.

### 7-3. 다음 날 밴드 조정 `adjustBandNextDay` [SETTLED — v1 표 폐기, 온보딩 Part 3 조정표도 미채택]

> **팀 결정 2026-07-24:** 온보딩 문서 Part 3의 "다음날 난이도 조정(회고 기반)" 표(완료+쉬움 +1 / 완료+버거움 유지 또는 −1 등)는 **채택하지 않는다.** 다음날 조정은 우리가 새로 설계한 아래 **day_result 3분기** 방식으로 한다(핵심 차이: 완료→하향 칸 없음, 타깃 외 활동만 한 날을 −1로 처벌하지 않음).

**신호 집계 (타깃 슬롯 1·2만 밴드에 반영):**
```
day_result:
  ① 타깃 슬롯 ≥1 완료           → "완료"      (아래 표 적용)
  ② 즐거움/회피만 완료           → "유지"      (ΔB=0, consecutive_miss 리셋)
  ③ 아무것도 완료 안 함          → "미완료"    (ΔB=−1, consecutive_miss +1)
M_band = 완료 타깃 슬롯 M 평균(반올림)
T_band = 완료 타깃 슬롯 토글 최댓값
P_day  = 그 날 완료한 전 슬롯 P 평균
적용: B = clamp(B + ΔB, L1, Ln)   # 상·하한 클램프
```

| day_result | M_band | T_band | ΔB | 부가 동작 |
|---|---|---|---|---|
| 완료 | ≥4 | 도전 | **+1** | 축하 강화 |
| 완료 | ≥4 | 보통/가볍게 | 0 (`nudge_streak` 2 도달 시 +1) | 토글 기본값 '보통' 넛지 |
| 완료 | 3 | any | 0 | — |
| 완료 | ≤2 | any | 0 | 위로 1줄; `low_m_streak` 2회 시 토글 '가볍게' 복귀; (P_day ≤2면) 즐거움 가중치↑ |
| 즐거움/회피만 완료 | — | — | **0** | 완료 축하 동일 |
| 미완료 | — | — | **−1** | 회피 슬롯에 더 작은 버전 예약 |
| 2일 연속 미완료 | — | — | **L1 리셋** | 위로 메시지, 다음 날 생활리듬부터 |

- **정합성 불변식: 완료(어떤 형태든)→하향 칸 없음.** 하향은 오직 완전 미완료(③)에서만.
- **넛지 상태기계(양방향, 내부 전용):**
  - 상향 `nudge_streak`: (완료 & M_band≥4 & T_band∈{보통,가볍게}) 연속. 조건 아닌 날 0 리셋. 2 도달 시 ΔB=+1 발동 후 0.
  - 하향 `low_m_streak`: (완료 & M_band≤2) 연속 2회 → 다음날 토글 기본값 '가볍게' 복귀(밴드 불변, 체감만 완화).
- **P의 역할(밴드 미개입):** 완료 P를 `소재` 축별 `P_pool`에 누적 → 즐거움 슬롯 가중치. P·M 누적 평균은 마이페이지 표시용.
- 연속 카운터·`nudge_streak`·`low_m_streak`은 **UI 비노출**.

- **사진 인증 칭찬** [유지]: 완료 후 사진 → LLM(12초) 1~2문장 칭찬. 미션 무관해도 시도 자체 칭찬. 결정적 가드(규정 언어·난이도·스트릭 표현 섞이면 폐기·대체). 분석 실패해도 완료 인정.
