## 1. 온보딩 (별도 담당 — 사이클은 인터페이스만 계약)

**[v2]** 온보딩은 스토리텔링 심리교육 + 가치 명료화 + 약 1주 온보딩 미션으로 재설계(별도 담당). 사이클은 다음 시작 데이터만 받는다:

| 필드 | 용도 |
|---|---|
| `mood_baseline` | 마이페이지 변화 그래프 기준선 |
| `pm_pattern` | 즐거움 슬롯 초기 추천 시드 |
| `skip_pattern` | 회피 슬롯 초기화(§3-1 조기 활성화 판정 포함) |
| `interests` | 즐거움 슬롯 콜드스타트 폴백 + 미션 문구 개인화 |
| `stage` / `allowed_domains` / `band` / 게이트 플래그 | 분류기(`determineStage`) 산출 — v1 §1-2, 1-3 규칙 유지 |

단계 판정·허용 영역·타깃 영역 규칙(v1 §1-2, §1-3)은 **변경 없음**.

## 2. 데일리 설문 (매일, 2문항) **[v2 전면 개정]**

1. **기분/컨디션** — 5단계 탭 1회 (매우 별로 / 별로 / 보통 / 좋음 / 매우 좋음)
   - **[v2 확정 2026-07-20] 알고리즘도 5단계로 통일** (변환표 없음). v1의 3단 컨디션이 하던 역할은 5단 임계로 직접 재정의:
     - 난이도 보정(§4-1)의 "바닥" 판정 = **기분 ≤ 2**
     - 카테고리 최소 컨디션 게이트 = **기분 ≥ 3** (v1의 "그저 그럼 이상"에 대응)
     - 기분 그래프·베이스라인 비교도 같은 5단 원값 사용 — 저장 값이 하나로 통일됨.
2. **활동 선택** — "오늘은 어떤 걸 해보고 싶나요?"
   - 타깃 영역의 하위 활동만 노출, 카테고리 게이트 통과분만 표시, 전부 닫히면 스텝다운, "잘 모르겠어요" 가능 (v1 §2 규칙 유지).
   - **[v2 결정] activityId → 슬롯 매핑:** 선택 활동은 **타깃 슬롯 1번**에 반영으로 고정. 즐거움 슬롯 후보와 소재가 겹치면 **타깃이 우선**하고 즐거움 슬롯은 차순위 소재로 대체(같은 날 소재 중복 금지 — diversity 축과도 정합).
3. ~~관심사~~ → **[v2] 데일리에서 제거.** 온보딩 수집 + **주 1회 갱신 카드**("요즘 빠져있는 게 있나요?", 건너뛰기 가능)로 이동. P 평정이 높았던 소재는 관심사 풀에 자동 추가.
   - 관심사(선언) vs P 누적(행동)이 다른 방향일 때: 즐거움 슬롯은 **P 데이터 우선**, 단 갱신 직후 3일간은 새 관심사에 부스트 가중치(선언을 무시하지 않는다는 신호).

## 3. 미션 생성 **[v2 전면 개정]**

### 3-1. 슬롯 구성 (v1: 타깃 2 + 랜덤 2 → v2: 타깃 2 + 즐거움 1 + 회피 1)

| 슬롯 | 내용 | 배지 |
|---|---|---|
| 1–2 타깃 | 타깃 영역, 난이도 서로 다르게. 슬롯 1 = 설문 선택 활동 반영 | "내가 고른 영역" + 가치 연결 문구 |
| 3 즐거움 | P 누적 가중치 상위 소재에서 추천 | "최근 즐거움 점수가 높았어요" |
| 4 회피 | 반복 skip 대상을 한 단계 작게 쪼갠 시드(더 낮은 밴드) | "계속 미뤄왔던 조각, 더 작게 쪼갰어요" |

- **첫 주는 3슬롯**(회피 미노출). **[v2 결정] "2주차" 기준 = 본 사이클 시작일 기준.** 단 온보딩 `skip_pattern`에 같은 세부 영역 명시적 skip ≥ 2회가 있으면 1주차부터 조기 활성화 허용.
- 2주차 이후에도 skip 데이터가 없으면 슬롯 4는 타깃 다양성 미션으로 대체(회피할 게 없는 건 좋은 신호).
- **후보풀 = 허용영역 ∩ 게이트.** 게이트·영역 제약은 어떤 경우에도 완화하지 않는다. 후보 부족 시 다양성 제약만 완화(2축→1축→해제), 그래도 부족하면 슬롯 수 축소(빈 슬롯·중복 노출 금지).

### 3-2. 영역 내 다양성 (저단계 붕괴 수용)

시드에 `diversity_key` 3축(소재/시간대/감각) 부여. 그 날 슬롯들이 **최소 2개 축 각각에서 서로 다른 값 2개 이상**이면 충족. 관심사 태그는 소재 축 값.

### 3-3. skip의 조작적 정의

- **명시적 skip** = 건너뛰기 탭 또는 회피 프롬프트 응답 → 회피 후보 자격(2주 창 내 같은 미션/세부영역 2회) 카운트 포함.
- **무응답일**(미접속 포함) = 회피 데이터 제외, 밴드 미완료 경로에는 포함.
- 우선순위 = skip 횟수 내림차순, 동률 시 최근성.

### 3-4. 생성 파이프라인·문구 규칙

v1 §3-3(LLM 생성→결정적 검증·수리→폴백), §3-4(카테고리 게이트), §3-5(문구 규칙) **유지**. 구성 밸런스만 새 슬롯 구조 기준으로 갱신: 관심사 반영은 즐거움 슬롯 + 타깃 1개까지, 사진 인증 가능 1개 이상.

## 4. 난이도 결정 **[v2 전면 개정]**

### 4-1. 오늘의 시도 난이도 — **[논의 중 2026-07-20]** 합성 방식 미확정

밴드 B, 기분 보정(기분 ≤2일 때), 토글 T(가볍게 −1/보통 0/도전 +1, 기본값 가볍게) 세 신호를 어떻게 합칠지는 **다음 회의에서 결정**한다. 공통 전제: 토글은 밴드의 하루짜리 ±1 표현, 영역캡(v1 §3-2)은 항상 상한, 클램프는 마지막에 한 번.

**BA 이론 레퍼런스 (토의용):**

| 출처 | 난이도/강도에 대해 말하는 것 | 우리 논점과의 연결 |
|---|---|---|
| Lejuez et al. 2001·2011, *BATD 매뉴얼* (Behavior Modification) | **활동 위계(activity hierarchy)**: 활동 15개를 쉬움→어려움 순으로 서열화하고, **아래 단계의 숙달(mastery)이 확인되어야 위로 진행**. 난이도는 치료자–내담자 협업으로 정함 | 밴드 = 위계, M→밴드 상향 = 숙달 조건부 진행. 우리 구조의 원형 |
| Martell et al., *Behavioral Activation for Depression* (10대 원칙) | **"기분이 아니라 계획에 따라 행동하라(act according to a plan, not a mood)"** — outside-in. 기분을 행동의 결정 변수로 삼는 것 자체가 우울의 악순환 | **기분 바닥이라고 시스템이 난이도를 자동으로 깎는 것은 BA 정신과 긴장 관계**라는 반론의 근거 |
| Beck et al. 1979, *인지치료* — graded task assignment | 성공 확률이 높은 작은 단계부터. 실패 경험 방지가 최우선 | 기분 나쁜 날 실패 확률이 높다면 낮추는 게 정당하다는 찬성 근거 |
| dialecticalbehaviortherapy.com — successive approximation | 목표 행동을 점진적 근사로 쪼갬. 못 한 날은 "더 작은 버전"으로 | 우리 회피 슬롯(TRAP→TRAC 재축소)과 동일 논리 |
| JMIR Mental Health 2024 (자동화 BA 앱 RCT) | 완전 자동화 BA 앱도 효과 — 단 활동 제안의 개인화·점진성이 핵심 성분 | 알고리즘형 난이도 조정의 타당성 근거 |

**제안안 3가지 (레퍼런스 기반):**

| | A안 — 합산형 | B안 — 계획 우선형 (Martell) | C안 — 안전 우선형 (Beck/graded) |
|---|---|---|---|
| 공식 | `clamp(B + 기분보정 + T)` | `clamp(B + T)` — 기분은 실제 난이도에 불개입, **토글 기본값만** 기분 따라 조정(≤2면 기본 '가볍게' 강제) | `clamp(B + T)`이되 기분 ≤2인 날은 **'도전' 선택지 숨김**(상한 = B) |
| 철학 | 세 신호 동등 | "기분이 아니라 계획대로" — 기분은 추천에만 반영, 선택은 침해 안 함 | 실패 경험 원천 차단 |
| 장점 | 단순, 예측 가능 | BA 원칙에 가장 충실. 기분 나쁜 날 '도전'을 골라 해내는 교정적 경험 허용 | 저단계 유저 보호 최대 |
| 단점 | 기분 나쁜 날 '도전'을 골라도 실제로는 '보통'이 됨 — 유저 선택이 조용히 무력화 | 기분 바닥+도전 조합의 실패 위험을 유저가 짊어짐 | 선택지 제거가 "오늘은 안 된다"는 평가로 읽힐 위험(§1 낙인 우려) |

*작성자 소견: B안이 BA 원칙(기분 독립 행동 + 협업적 난이도 결정)과 우리 §1(선택권 존중)에 동시에 부합. 실패 위험은 미완료 시 −1·재축소 경로가 이미 흡수한다.*
- **토글 기본값 넛지(양방향):**
  - 상향: `nudge_streak`(완료 & M높음 & 토글 보통/가볍게 연속) 2 도달 → 다음날 기본값 '보통'.
  - 하향 **[v2]**: 완료 & M낮음 연속 2회 → 다음날 기본값 '가볍게' 복귀. (밴드 불변, 체감 부담만 완화.)

### 4-2. 사후 P/M 평정 **[v2 결정]**

- UI: **0–10 연속 슬라이더 2개**(즐거움 P, 뿌듯함 M), **완료 미션에만**.
- **초기값 없음** — 핸들은 터치 시 등장. 슬라이더 미조작 상태로 완료 시 내부 **중립(3)** 기록. (초기값이 있으면 무성의 응답이 밴드를 밀어 올리는 오염 발생.)
- 내부 5구간 매핑: 0–2→1, 3–4→2, 5–6→3, 7–8→4, 9–10→5. 임계: 높음 ≥4, 중립 =3, 낮음 ≤2.
- 근거: BA/CBT 원전(활동 기록지의 Mastery & Pleasure 평정)이 0–10 척도. 7점 척도의 학술 근거는 없음 — 기존 초기값 7은 척도가 아니라 목업 기본값이었다.

### 4-3. 다음 날 밴드 조정 (`adjustBandNextDay` 재작성) **[v2 — v1 §4 표 대체]**

**신호 집계(타깃 슬롯 1·2만 밴드에 반영):**
- `day_result` 3분기 — ① 타깃 1개 이상 완료 = 완료 / ② **즐거움·회피만 완료 = 유지(ΔB 0, 연속 미완료 카운터 리셋)** / ③ 아무것도 완료 안 함 = 미완료.
- `M_band` = 완료 타깃 슬롯 M 평균(반올림), `T_band` = 완료 타깃 토글 최댓값, `P_day` = 그 날 완료 전 슬롯 P 평균.

| day_result | M_band | T_band | ΔB(다음날) | 부가 동작 |
|---|---|---|---|---|
| 완료 | ≥4 | 도전 | **+1** | 축하 강화 |
| 완료 | ≥4 | 보통/가볍게 | 0 (`nudge_streak` 2 도달 시 +1) | 토글 기본값 '보통' 넛지 |
| 완료 | 3 | any | 0 | — |
| 완료 | ≤2 | any | 0 | 위로 한 줄, 연속 2회 시 토글 '가볍게' 복귀, (P_day ≤2면) 즐거움 가중치↑ |
| 즐거움/회피만 완료 | — | — | **0** | 완료 축하는 동일하게 |
| 미완료 | — | — | −1 | 회피 슬롯에 더 작은 버전 예약 |
| 2일 연속 미완료 | — | — | L1 리셋 | 위로 메시지, 다음 날 생활리듬부터 |

- **정합성 체크: 완료(어떤 형태든)→하향 칸 없음.** 하향은 오직 완전 미완료에서만.
- v1의 부담 이모지 문항은 **폐지** — 토글 선택 + M이 대체. 사후 설문 문항 순증 없음.
- 연속 카운터·`nudge_streak`은 내부 상태, UI 비노출.

**P의 역할(밴드 미개입):** 완료 P를 소재 축별 누적 → 즐거움 슬롯 가중치. P·M 누적 평균은 마이페이지 표시용.

## 5. 단계 진급 (신설) **[v2]**

- **주 1회 배치.** 밴드(일 단위)와 독립.
- **트리거(전부 AND):** ① 최근 2주 완료율 ≥ 60% — **분모 = 타깃+즐거움 제안 수(회피 제외), 회피 완료는 분자 보너스** ② 2주 창 타깃 영역 완료 ≥ 3회 ③ M 추세 비하락 — **첫 평가 기간은 ③ 면제(①②만)**.
- 발동 시: 자동 승급 금지 → "다음 조각으로 넘어가볼까요?" 동의 탭 → 동의 시 새 영역 게이트 재확인 → 통과해야 노출. 거절 시 2주 뒤 재제안. **강등 없음.**
- **[v2 결정] 금지조건 독립 재평가:** 진급과 별개로 **4주마다** 금지조건 1개에 대한 가벼운 확인 1문항(예: "요즘 전화는 어때요?" 탭 1회)으로 게이트 플래그만 갱신. 진급이 늦어도 게이트가 영구 고착되지 않게 하는 안전판. 재평가로 게이트가 열려도 단계·밴드는 불변.
- **정체(4주+ 무진전):** (a) L1 재-콜드스타트 + 즐거움 가중치↑ (b) 관심사 재수집 (c) 무기력/위기 신호 체크 → 자원 연결. 실패 프레이밍 금지.
